เตรียมก่อนวันอบรม

รายการที่ทำวันอบรมแล้วไม่ทัน ต้องเสร็จก่อนอย่างน้อยหนึ่งวัน

  • ยืนยันว่าผู้บริหารทั้ง 5 ท่านสมัคร Claude Pro แล้ว และล็อกอินได้จากโน้ตบุ๊กที่จะนำมา ถ้ามีท่านใดยังไม่ได้สมัคร ต้องกันเวลาช่วง 09:00 ไว้ 15 นาที และตารางจะขยับทั้งวัน — รู้ก่อนดีกว่ารู้ในห้อง
  • เปิดหน้าจอ Claude จริงเดินทัวร์เมนูซ้อมหนึ่งรอบ หน้าจอมีการปรับปรุงเป็นระยะ ตำแหน่งปุ่มและชื่อเรียกอาจไม่ตรงกับที่เขียนในคู่มือ — เดินทัวร์ตามฟังก์ชัน ไม่ใช่อ่านตามเอกสาร
  • เตรียมไฟล์ zip ของ Skill กำหนดเองสองตัว (วินัยการทำงาน · ซักค้านแผน) ไว้แจก สองตัวนี้ไม่ได้อยู่ในไดเรกทอรีสำเร็จรูป ถ้าไม่มีไฟล์แจก ผู้เรียนจะหาไม่เจอแล้วเรื่องนี้จะจบแค่ในห้อง
  • เตรียม Routine ตัวอย่าง 1 ตัว และทดสอบ Dispatch จากมือถือตัวเองให้ผ่าน สองเดโมนี้อยู่คนละผลิตภัณฑ์ (Claude Code / Cowork) และพังง่ายที่สุดของวัน — ถ้าซ้อมแล้วไม่เสถียร อัดวิดีโอหน้าจอสำรองไว้
  • ซ้อมเดโม Demo2 และ Demo3 กับไฟล์จริงจนจบ ผลลัพธ์ของโมเดลไม่เหมือนกันทุกครั้ง ต้องรู้ว่าคำตอบหน้าตาประมาณไหน และถ้าออกนอกทางจะดึงกลับด้วยประโยคอะไร
  • อ่านเฉลยใน dataset/README.md ให้จบ ความผิดปกติ 3 จุดในไฟล์ยอดขาย และช่องว่าง 3 ข้อระหว่างประกาศกับ SOP — ต้องรู้คำตอบก่อนเข้าห้อง
  • ตรวจเงื่อนไขการใช้ข้อมูลและราคาแผนสำหรับองค์กรจากหน้าเว็บของ Anthropic ณ วันนั้น สองเรื่องนี้เปลี่ยนได้ ห้ามตอบผู้บริหารจากความจำ — เปิดหน้าจริงให้ดูในห้องดีที่สุด
  • เตรียมไวท์บอร์ดหรือฟลิปชาร์ตที่เขียนแล้วไม่ต้องลบทั้งวัน ลิสต์งานของผู้เรียนตอนเช้าคือวัตถุดิบของช่วงบ่าย ถ้าลบทิ้งช่วง M4 จะพัง

แบบประเด็นที่ต้องพูด
Claude Chatที่ใช้ทั้งวันนี้ — เว็บ มือถือ เดสก์ท็อป ถาม-ตอบ ไฟล์ Artifacts Projects
Claude Coworkมอบหมายงานเป็นชิ้นให้ทำจนจบ ทำงานกับโฟลเดอร์ · งานตั้งเวลา · สั่งจากมือถือ · ต้องติดตั้งแอปเดสก์ท็อป
Claude CLI (Claude Code)สายเทคนิค ทำงานกับโค้ดและระบบ ตั้ง Routines — ทีม IT ของเราจะใช้แบบนี้
ข้อควรระวังที่ต้องพูด — กติกา 3 ถังใช้เหมือนกันทุกแบบ และ Cowork/CLI เข้าถึงไฟล์ในเครื่องได้กว้างกว่า ยิ่งมีสิทธิ์มาก ยิ่งต้องคิดก่อนให้สิทธิ์

09:38 – 09:52 · เจาะ Cowork + เดโมสด

อธิบายวงจรสามขั้นตามสไลด์: มอบหมาย+ชี้โฟลเดอร์ → ทำจนจบเอง → ส่งมอบไฟล์ผลงาน แล้วมอบหมายงานจริง 1 ชิ้นบนเครื่องวิทยากร เช่น สรุปโฟลเดอร์อีเมลลูกค้าเป็นรายงาน 1 หน้า ปล่อยให้ทำระหว่างสอนต่อ กลับมาเปิดผลตอนท้ายช่วง — ประเด็นที่ต้องให้เห็นคือ “ไม่ต้องนั่งเฝ้า”

ปิดด้วยตาราง Chat หรือ Cowork: งานโต้ตอบและวิเคราะห์ไฟล์ที่เลือกเอง = Chat · งานเป็นชิ้นหลายขั้นและงานประจำตามเวลา = Cowork

สองข้อควรระวังที่ต้องพูด — ข้อสองสำคัญกว่าที่คิด
หนึ่ง Cowork ต้องติดตั้งแอปเดสก์ท็อป · สอง มันอ่านได้ ทุกไฟล์ ในโฟลเดอร์ที่เราชี้ให้ ไม่ใช่แค่ไฟล์ที่เราคิดถึงตอนสั่งงาน

ความต่างที่ต้องทำให้ผู้เรียนเห็น — ใน Chat เราเลือกไฟล์ทีละไฟล์ เห็นกับตาว่าอัปโหลดอะไรเข้าไป จะพลาดก็ต่อเมื่อเจตนาเลือกผิด แต่ใน Cowork เราชี้ทั้งโฟลเดอร์ จึงพลาดได้โดยไม่มีใครทำอะไรผิด แค่ลืมว่ามีอะไรอยู่ในโฟลเดอร์ก็พอ

ตัวอย่างที่ใช้เล่าในห้อง — ชี้ Cowork ไปที่โฟลเดอร์ชื่อ “งานไตรมาส 3” เพราะอยากให้สรุปยอดขาย แต่ในนั้นมีคนเคยก๊อป batch record กับผลตรวจ stability มาวางไว้เมื่อสองเดือนก่อนตอนเตรียมประชุม เจ้าของโฟลเดอร์ลืมไปแล้วว่ามันอยู่ในนั้น พอ Cowork อ่านทั้งโฟลเดอร์ เอกสารถังแดงก็ออกไปด้วยโดยไม่มีใครตั้งใจ

กติกาสามข้อที่ให้ผู้เรียนจำกลับไป (อยู่บนสไลด์แล้ว)

  1. เปิดโฟลเดอร์ดูก่อนทุกครั้ง ว่ามีอะไรอยู่ในนั้นบ้าง
  2. เลือกโฟลเดอร์ที่แคบที่สุด เท่าที่งานต้องใช้
  3. ถ้ามีไฟล์ถังแดงแม้แต่ไฟล์เดียว ย้ายออกก่อน หรือสร้างโฟลเดอร์ใหม่ใส่เฉพาะไฟล์ที่งานนี้ต้องใช้
ก่อนวันอบรม — เตรียมโฟลเดอร์อีเมลสมมติบนเครื่องวิทยากร และซ้อมเดโม Cowork ให้ผ่านหนึ่งรอบ ถ้าไม่เสถียร อัดวิดีโอหน้าจอสำรอง

ราคาเปลี่ยนได้ ให้เปิดหน้าราคาที่ตรวจไว้ก่อนวันอบรมขึ้นจอ อย่าตอบเป็นตัวเลขจากความจำ

สิ่งที่ตอบได้เป็นหลักการ: แผนสำหรับองค์กรคิดค่าใช้จ่ายต่อผู้ใช้ต่อเดือน และสิ่งที่ได้เพิ่มจากบัญชีส่วนตัวคือ การจัดการสมาชิกจากศูนย์กลาง การตั้งค่าระดับองค์กร และเงื่อนไขข้อมูลที่ทำสัญญากับบริษัทได้

วิธีตอบที่ผู้บริหารรับได้ดีที่สุดคือเปลี่ยนคำถามจาก “แพงไหม” เป็น “เทียบกับเวลาที่ประหยัดได้เท่าไหร่” ชี้กลับไปที่งานที่เพิ่งทำใน M2 แล้วถามว่าถ้างานนั้นเกิดขึ้นทุกสัปดาห์ มูลค่าของเวลาที่ประหยัดได้เท่าไหร่ แล้วเสนอให้เริ่มจากกลุ่มนำร่องเล็กๆ ก่อน ไม่ต้องซื้อทั้งบริษัทตั้งแต่แรก

IT จะควบคุมได้แค่ไหน ดูได้ไหมว่าใครใช้อะไร

ตอบตรงๆ ว่า ตอนนี้ควบคุมไม่ได้เลย เพราะทุกคนใช้บัญชีส่วนตัว บริษัทไม่รู้ว่าใครใช้ ใช้กับข้อมูลอะไร และไม่มีทางระงับการเข้าถึงเมื่อพนักงานลาออก

นี่ไม่ใช่ข้อเสียของเครื่องมือ แต่เป็นข้อเสียของ วิธีที่เราใช้อยู่ตอนนี้ — และรายงานประชุมวาระที่ 8 บันทึกไว้แล้วว่าฝ่ายเทคโนโลยีสารสนเทศพบการใช้งานผ่านบัญชีส่วนตัวในหลายฝ่าย โดยบริษัทยังไม่มีนโยบาย ประเด็นนี้จึงมีอยู่แล้วไม่ว่าวันนี้เราจะอบรมหรือไม่

ทางออกคือย้ายไปแผนสำหรับองค์กรที่มีการจัดการสมาชิกจากศูนย์กลาง คู่กับการมีนโยบายเป็นลายลักษณ์อักษร ให้ตรวจรายละเอียดความสามารถด้านการกำกับดูแลจากเอกสารของ Anthropic ก่อนวันอบรม แล้วตอบตามนั้น

ถ้า auditor ถามว่าเราใช้ AI ทำเอกสารไหม เราตอบว่าอะไร

คำตอบที่ปลอดภัยและเป็นความจริงมีสี่ประโยค

  1. บริษัทใช้เครื่องมือนี้เป็น เครื่องมือช่วยร่าง ไม่ใช่ระบบที่ใช้ตัดสินคุณภาพหรือปล่อยผ่านผลิตภัณฑ์
  2. เอกสารทุกฉบับที่เข้าระบบคุณภาพ ผ่านการตรวจสอบและอนุมัติโดยผู้มีอำนาจตามระบบคุณภาพ เหมือนเดิมทุกขั้นตอน
  3. บริษัท ไม่นำข้อมูลที่อยู่ในขอบเขต GxP เช่นสูตรตำรับ ข้อมูลทะเบียนยา batch record หรือผล stability เข้าเครื่องมือที่ยังไม่ผ่านการประเมิน
  4. ถ้าจะใช้กับงานที่กระทบ GxP ต้องมี การประเมินและมาตรการควบคุมเป็นลายลักษณ์อักษร ก่อน

สิ่งที่ต้องมีจริงเพื่อให้ตอบอย่างนี้ได้: นโยบายเป็นลายลักษณ์อักษร และร่องรอยการตรวจสอบเอกสาร ซึ่งบริษัทมีอยู่แล้วในระบบคุณภาพ ประเด็นคือต้องเขียนเรื่องเครื่องมือ AI เพิ่มเข้าไป

คำตอบที่ห้ามพูด คือ “ไม่ได้ใช้” ถ้าจริงๆ มีคนใช้อยู่ นั่นอันตรายกว่าการยอมรับตามความจริง

มันมั่วไหม เราจะรู้ได้ยังไงว่าที่มันตอบถูก

ตอบตรงว่า ผิดได้ และผิดแบบมั่นใจ อย่าปฏิเสธข้อนี้ เพราะผู้บริหารจะเจอเองภายในสัปดาห์แรก ถ้าเราบอกว่าไม่ผิดแล้วเขาเจอว่าผิด เขาจะเลิกใช้ทั้งหมด

วิธีคุมสี่ข้อ ที่ฝึกมาแล้วในช่วง 11:50

  • สั่งให้อ้างอิงว่าเอาคำตอบมาจากแถวไหน หน้าไหน ข้อไหน แล้วเปิดตรวจ
  • ถามซ้ำด้วยมุมที่ต่าง ถ้าคำตอบเปลี่ยนไปมาแปลว่ายังเชื่อไม่ได้
  • ตัวเลขที่จะเอาไปใช้ต่อ ตรวจด้วยมือทุกครั้ง
  • งานที่ตรวจไม่ได้ ไม่ใช้

เปรียบเทียบที่ผู้บริหารเข้าใจเร็ว: ปฏิบัติกับมันเหมือนผู้ช่วยใหม่ที่ขยันมากและอ่านเร็วมาก แต่เพิ่งเข้างานวันแรกและไม่รู้เรื่องบริษัทเรา — งานที่ผู้ช่วยใหม่ทำ เราตรวจก่อนเซ็นทุกครั้ง

แล้วจะเริ่มกับพนักงานยังไง

ลำดับที่แนะนำ สี่ขั้น ทำได้ในหนึ่งไตรมาส

  1. เขียนกติกา 3 ถังให้เป็นลายลักษณ์อักษรก่อน — รายงานประชุมวาระที่ 8 มอบหมายฝ่ายเทคโนโลยีสารสนเทศ ร่วมกับฝ่ายประกันคุณภาพไว้แล้ว ใช้ของวันนี้เป็นตัวตั้งได้
  2. เลือกกลุ่มนำร่อง 1 ฝ่ายที่งานไม่แตะข้อมูล GxP เช่นงานเอกสารโต้ตอบลูกค้าต่างประเทศ หรืองานสรุปรายงาน
  3. ย้ายกลุ่มนำร่องไปใช้แผนสำหรับองค์กร เพื่อให้ IT จัดการสมาชิกและตั้งค่าได้
  4. วัดผลด้วยเวลาที่ประหยัดได้จริง ไม่ใช่วัดด้วยจำนวนคนที่สมัคร

สิ่งที่ต้องเลี่ยง: ประกาศให้ทุกคนใช้พร้อมกันโดยไม่มีนโยบาย จะได้ผลลัพธ์เหมือนที่วาระที่ 8 รายงานไว้ คือมีคนใช้อยู่แล้วแต่บริษัทไม่รู้ว่าใช้กับข้อมูลอะไร

ทำไมวันนี้ไม่เทียบกับเครื่องมือ AI ตัวอื่นที่เราใช้อยู่

ถ้ามีใครถาม ตอบว่าเป็นความตั้งใจ และเหตุผลคือ การเปรียบเทียบสเปกไม่เปลี่ยนพฤติกรรมใคร สิ่งที่เปลี่ยนคือการได้เห็นงานของตัวเองเสร็จตรงหน้า

แล้วโยนกลับไปที่ผู้ถาม: “ท่านลองเอาโจทย์ที่เราทำวันนี้ไปลองกับเครื่องมือที่ท่านใช้อยู่ก็ได้ครับ แล้วท่านจะตอบคำถามนี้ได้เองดีกว่าที่ผมตอบ” — ข้อสรุปที่เขาคิดเองจะฝังแน่นกว่าที่เราบอก

แผนสำรองเมื่อเวลาไม่พอ

ตัดตามลำดับนี้เท่านั้น อย่าตัดข้ามลำดับ เพราะสองรายการท้ายคือเป้าหมายของวัน

  1. ตัดทัวร์ฟีเจอร์ 15:25 – 15:45 ทั้งช่วง ได้คืน 20 นาที กระทบเป้าหมายน้อยที่สุด แต่ต้องแทรกคำเตือนเรื่องห้ามเชื่อม Connectors ด้วยบัญชีส่วนตัวไว้ในช่วงปิดวงแทน
  2. ตัดเดโมที่สองของ M2 (11:05 – 11:15) ได้คืน 10 นาที แต่ต้องยังเปิดไฟล์รายงานประชุมให้เห็นสักครั้งว่ามันอ่านเอกสาร 10 หน้าได้
  3. ลดโจทย์ลงมือของ M1 จากแก้ต่อ 2 รอบเป็น 1 รอบ ได้คืน 8 นาที แต่ต้องยังสอนหลักการแก้งานต่อให้ครบ
  4. ลดรอบโชว์ Project จาก 1 นาทีต่อคนเป็นให้ 2 ท่านโชว์ ได้คืน 5 นาที เก็บช่วงลงมือไว้ให้ครบ
  5. ห้ามตัด: ช่วงลงมือสร้าง Project 14:25 – 15:00 ถ้าตัดช่วงนี้ เป้าหมายหลักของวันไม่เกิด และผู้บริหารจะกลับบ้านพร้อมของที่ยังใช้ไม่ได้
  6. ห้ามตัด: รอบคำมั่น 16:15 – 16:30 ถ้าตัดช่วงนี้ ความตั้งใจจะระเหยภายในสัปดาห์เดียว และวันนี้จะไม่นำไปสู่อะไรเลย
